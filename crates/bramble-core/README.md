# bramble-core

The Bramble wallet's core: [`wallet-core`](../wallet-core) plus Bramble's own choices, exported
through UniFFI as one library for the browser extension (wasm32, npm
`@starknet-innovation/bramble-core`), iOS (Swift, XCFramework) and Android (Kotlin, JNI).

## What it is

- **Bramble's policy.** The OpenZeppelin account version Bramble deploys (`OZ_ACCOUNT_VERSION`),
  the salt its `KmsPort` defaults to, its multisig coordination policy (`coordination`: the
  `bramble.multisig` identifier, the default relays and "one custom relay replaces them", the page
  cap, the sync window, recipient selection and the sender rule), its portfolio and history
  choices (`PORTFOLIO_POLICY`, `HISTORY_POLICY`), and, under `mobile`, the mobile vault's schema
  and migration chain.
- **Bramble's catalogs.** `catalogs` embeds `generated/` (`networks.json`, `token-registry.json`,
  `accounts.json`, `multisig.json`, rendered by Bramble's `bun run mobile:assets` and copied
  unchanged) and parses each once: the networks and token registry `wallet-core` takes as
  `Catalogs`, the account classes with `resolve_class`, `argent_shape` and `send_authorization`,
  and the pinned multisig class and limits. A file that does not parse fails loudly on first use.
  `tests/catalogs.rs` holds each to its copy under `tests/fixtures/`. The `mobile` feature exports
  them through UniFFI as mobile's core did.
- **The only FFI crate.** UniFFI scaffolding, `CoreError`, `core_info()`, and remote exports of
  `wallet-core`'s records. Functions keep the names and argument order of the extension's
  `KmsPort`. Built as `lib`, `cdylib` and `staticlib`; `uniffi.toml` keeps mobile's module names.
- **The gate on raw keys.** The `raw-keys` feature (default, for the extension) exports the
  functions that take or return a raw Stark private key. The `extension` feature (default, implied
  by `raw-keys`) exports the extension's other KMS and Nostr functions, several of which take or
  return a recovery phrase. Mobile builds `--no-default-features` and gets neither: its phrase
  stays inside `WalletCore`.
- **The mobile wallet, behind `mobile`.** iOS and Android build
  `--no-default-features --features mobile`: the `WalletCore` object (vault, accounts, send,
  portfolio, history, privacy, multisig coordination), its records and free functions, and the
  mobile-only glue its module exports through (`biometric`, `backup`, `public_store`, the
  wrong-passphrase backoff in `security`), ported unchanged from Bramble's `mobile/core`
  (`docs/PLAN.md`, 2.7). Its modules sit at the crate root, declared in `src/mobile.rs`, which
  `lib.rs` includes, so the Swift and Kotlin names are mobile's. The extension's wasm32 build
  leaves it off. `testing` (implies `mobile`) adds the integration-test hooks; mobile's suite
  needs it (`cargo test -p bramble-core --features mobile,testing`).
- **The mobile vault chain.** `src/migrations.rs` runs mobile's payload chain, v1 → v5
  (`VAULT_VERSION`), inside the DEK container (`src/account_store.rs` is the v5 schema). It is
  being replaced, not extended: the vault switch in `docs/PLAN.md` has mobile write the
  extension's v13 payload in the same container and refuse anything older, since no mobile
  vault holds funds yet.
- **The parity suite.** `tests/parity.rs` holds the core to golden fixtures generated by the
  extension's real code paths; `tests/fixtures.rs` holds those files to the sha256 manifest in
  `tests/fixtures/README.md`. Mobile's regression files (vaults earlier mobile cores wrote, and
  the gift wraps Rust writes for the extension and the iOS UI suite) are in `tests/regression/`.

## What it is NOT

- **Not where wallet logic lives.** Derivation, signing, address computation and Nostr all live in
  `wallet-core`; this crate passes Bramble's constants in and converts types. If it isn't
  Bramble's choice or an FFI concern, it belongs in `wallet-core`.
- **Not a Krusty client.** It never names `krusty_kms`; everything goes through `wallet-core`.
- **Not a generic SDK.** It is on crates.io, but another wallet should depend on `wallet-core`
  directly or add its own `<wallet>-core` crate next to this one.
- **Not the JavaScript package.** The npm entry point and generated TypeScript live in `js/`; this
  crate is the Rust they wrap.
- **Not a source of fixtures.** Files under `tests/fixtures/` are copied unchanged from Bramble and
  never edited to make a test pass.

## Building

```bash
bash tools/check.sh rust                                   # clippy (default, mobile, wasm32) + tests
cargo test -p bramble-core                                 # this crate's tests
cargo test -p bramble-core --features mobile,testing       # with mobile's suite
```

The Swift/Kotlin generator is the `uniffi-bindgen` binary behind the `bindgen` feature.
`AGENTS.md` at the repo root has the rules for changing this crate.
